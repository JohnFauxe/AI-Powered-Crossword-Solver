Crossword Solve Loop

The model never fills the grid. It suggests ranked answers for each clue. A separate search, with no AI in it, picks the set of answers whose crossings agree. The two take turns, and each round the letters from crossing words make the model's next question easier.

The loop

From clues to a filled grid

Blue boxes call the local model through Ollama. White boxes are plain numpy. The refine round runs up to 6 times, within a 600 s budget for the whole solve.

The refine rounds do most of the work. Letters correct after the first search vs. at the end: uc 112 → 138, wsj 50 → 89, ucs 127 → 187, wp 129 → 208.

A 7B model is much better at picking the answer out of a short list than at producing a word of the right length itself. That is why letters from crossings feed into a multiple-choice question rather than just being added to the prompt. Putting the pattern in the prompt only got recall@20 to about 0.33.

src/crossword/solver/search.py

How the grid search decides

Each cell holds one letter. Each slot is a factor that scores whatever string its cells spell. The search passes messages between cells and slots until their letter odds settle, then cleans up the best guess with local moves.

What a slot thinks its answer could be

On the first pass, a slot gives only 32% of its probability to the model's list. The rest goes to two fallbacks. Because of this, any letter string is allowed, so one clue the model can't answer doesn't force wrong letters into the words crossing it.

model list 32%
dictionary 34%
any string 34%

The miss rate is 0.68 on the first pass, split half and half. “Any string” is scored by a letter-pair model trained on every listed word. A slot's miss rate drops to 0.10 once its answer is verified, and to 0.15 for clue-DB answers in lookup mode.

the biggest single gain

Only trusted crossers supply letters

The search is overconfident: cells it rated 90% or higher were only about 66% right. If a slot is re-asked using letters its own wrong guess put there, the model just gives the same wrong guess again, and early versions of the loop got worse each round. Now a crossing letter is used only if the crossing word came from a list where the model read that clue, with confidence ≥ 0.5.

Letters you typed yourself are always part of the pattern and are never overwritten.

review

Strengths and open problems

Works well
  • The work is split cleanly. The model suggests and the search settles conflicts, so each part can be measured on its own. The README has an ablation for each technique.
  • The tests are held out properly. The puzzles are from Nov 2026 and the clue DB from 2022. Model-mode examples never share the slot's answer length, and the one setting that could leak is labelled LEAKY.
  • Answers are cached by model, prompt version and options, so re-runs and benchmarks are cheap.
  • Hand-entered letters are fixed. They feed the patterns and the solver never overwrites them.
Open problems
  • The default model is probably the wrong one. gemma3:12b is about 21 points ahead on both letters and words and only about 1.3× slower. Run it on the two 21×21 puzzles (ucs, wp) to decide whether to switch.
  • The first pass is the bottleneck. Only about 29% of clues get the right answer in their first list. A better first pass helps the most. qwen3's thinking mode hasn't been measured yet.
  • Verify can't lock in answers. It approved 88 wrong guesses at P > 0.9 against 19 right ones. It is only useful for rejecting strings the crossings spelled.
  • Results vary a lot between runs, on few puzzles. One changed list can send the loop down a different path, and each ablation rests on two puzzles. More test puzzles would make tuning more trustworthy.
  • Multiple choice only works with a short list. It finds the answer among a few dozen choices but rarely among hundreds, so slots with few known letters stay hard.
